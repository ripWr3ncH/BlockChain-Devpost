OVERVIEW
--------
International blockchain hackathon inviting developers, innovators, students,
researchers, designers, and technology enthusiasts to build decentralized
solutions using the Midnight ecosystem.

Theme: "From Midnight Ideas to On-Chain Innovation" — build practical solutions
addressing real-world problems using decentralized systems, smart contracts,
privacy, digital assets, Web3 infrastructure, and emerging blockchain tech.

Sponsor: Midnight
Organizer: ACTS EDC
Format: Online, public event

ELIGIBILITY
-----------
- Participant must be above the legal age of majority in their country of residence.
- Students only — companies and professional organizations are excluded.
- Open to all countries/territories except standard Devpost exclusions.

CORE SUBMISSION REQUIREMENTS
-----------------------------
1. Build a full-stack application on the Midnight ecosystem (front-end + back-end,
   not just a smart contract).
2. Use Midnight technology meaningfully within the project (not a superficial
   integration) — "Projects that do not demonstrate a functional Midnight
   integration may not qualify."
3. Deploy the project's smart contract(s) on Midnight Preview or PreProd network
   (this is the key change vs. the BD-specific version — must actually be a
   Midnight-based chain, not a generic/other blockchain).
4. Provide a working application demonstration (demo video / live demo).
5. Provide clear documentation and setup instructions (README, run steps).
6. Complete all work within the hackathon timeline (no pre-existing projects).

NEXT STEPS  (in priority order)
--------------------------------------------
1. RECORD THE DEMO VIDEO.  Blocking. ~30 minutes.
   This is requirement 4 and the only thing standing between the project and a
   complete submission. Everything it needs already runs locally.

     a. Start the three services (see DEMO.md section 0):
          docker run -d -p 6300:6300 midnightntwrk/proof-server:8.1.0             midnight-proof-server -v
          cd midnight/contracts/commitment && npm run bridge
          npm --prefix web run dev
     b. Sanity-check first:  node scripts/midnight-smoke.mjs   -> must print PASSED
     c. Follow DEMO.md. Target 5 minutes. The narration is written out.
     d. Film BOTH refusals, they are the whole argument:
          - write-off with too few approvals -> refused, then commits with enough
          - restructure at the sanctioning grade -> refused, then commits above it
     e. Say out loud what the screen cannot show: the director secrets and the
        officer's grade never reached the ledger. An absence does not demo itself.

   Gotcha: the Preview indexer intermittently returns
   "ServerError: An unknown error occurred" and kills a circuit call. It is
   testnet infra, not our code, and a retry fixes it. If it happens on camera,
   say "testnet hiccup, retrying" and carry on.

2. DEPLOY THE FRONT END so a judge has a URL to click.  ~15 minutes, free.
   Not a requirement, but three localhost services is a barrier most judges will
   not cross, and it costs marks on Presentation and UX.

     - Push web/ to Vercel (root directory: web).
     - Set NEXT_PUBLIC_MIDNIGHT_BRIDGE to a reachable bridge, or leave it unset
       and expect the "bridge unreachable" panel.
     - Understand what this does and does not give you: the page will show the
       live contract address and its on-chain state, but the BUTTONS will not
       work for a stranger unless a bridge is also publicly reachable. The bridge
       holds the funded wallet, so it cannot live in a browser.
     - Optional, ~1-2 hours: put the bridge + a proof server on a small VM to
       make the site fully clickable. The wallet seed then sits on a public
       server and anyone can spend the test tokens. Acceptable on a testnet,
       genuinely bad practice to present as a pattern.

3. REGISTER ON DEVPOST, if not already done. Nothing in this repo proves the
   team is registered, and no amount of code substitutes for it.

4. CONFIRM THE DEADLINE on the Devpost Timeline tab. The KEY DATES section above
   is scraped and self-evidently garbled: "Aug 26, 9:30pm EDT - Aug 27, 7:00am
   IST" describes two instants about 30 minutes apart, which cannot be a

5. Optional, only with time to spare:
