# Commitment contract — build status

`src/commitment.compact` compiles cleanly against `compact 0.31.1` (language version 0.23).
Verified in this repo by installing the Compact toolchain under WSL Ubuntu:

```
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/midnightntwrk/compact/releases/latest/download/compact-installer.sh | sh
compact update
compact compile src/commitment.compact src/managed/commitment
```

Output: 6 circuits (`originateLoan`, `appendEvent`, `registerDirector`, `confirmDirector`,
`revokeDirector`, `setRegulatoryConfig`) with prover/verifier keys and zkir under
`src/managed/commitment/`. `contract/index.js` + `.d.ts` are the generated TypeScript
contract binding for `services/api`.

## API/deploy layer — type-checked, not yet run live

`src/{witnesses,config,common-types,api,deploy}.ts` wire the compiled contract up to
midnight-js: wallet construction, provider bundle (privateState/publicData/zkConfig/proof/
wallet/midnight providers), deploy/join, and one function per circuit. The wallet/provider
plumbing in `api.ts` is adapted near-verbatim from the real, working
`midnightntwrk/example-counter` reference app (copy kept under `midnight/reference/`,
fetched from GitHub) — only the contract-specific parts are Verity's.

`npx tsc --noEmit` on these files against the actual installed `@midnight-ntwrk/*`
packages (`npm install` in this directory) passes with **zero type errors** — real
verification, not a guess. Two real bugs were caught and fixed this way:
- an off-by-one relative import path to the compiled contract module
- a duplicate-`ledger-v8`-version conflict between our direct dependency and the one
  `@midnight-ntwrk/midnight-js-protocol` pins internally (fixed by pinning our
  `ledger-v8` to the exact `8.1.0` midnight-js-protocol expects, so npm dedupes to one
  copy instead of two incompatible ones)

**Not yet done: an actual live deployment.** `deploy.ts` is ready to run
(`npm run deploy:preprod` after setting `MIDNIGHT_WALLET_SEED`, with a local proof server
running via `docker run -p 6300:6300 midnightntwrk/proof-server:8.1.0 midnight-proof-server -v`),
but has not been executed against a funded wallet in this session.

To get a funded Preprod wallet: create one (the seed can be freshly generated by
`deploy.ts` itself if `MIDNIGHT_WALLET_SEED` is unset — it will print and wait), then fund
its unshielded address via the Preprod faucet at **https://faucet.preprod.midnight.network/**
(this is the address confirmed from the working example app; an earlier faucet URL quoted
from docs summarization, `midnight-tmnight-preprod.nethermind.dev`, may also work but
wasn't independently confirmed — prefer the one above).

## Known gaps before this is submission-ready

- `verifyBoardThreshold` compiles but is a stub — `validCount` is hardcoded to 0 rather
  than actually iterating `boardSignatures` against the `directors` ledger map. Needs a
  real k-of-n loop; Vector/Map iteration idioms need confirming against
  `compact compile --help` / stdlib docs, then re-verified with `compact compile`.
- `sanctioningSeniority`/ONE_LEVEL_ABOVE authority check is a placeholder — needs a real
  seniority credential/witness wired in.
- `exposure` and `claims` contracts (the other two Fabric channels) are not yet ported.
- No live deployment attempted yet — see above.
