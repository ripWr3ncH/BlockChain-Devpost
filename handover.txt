3. GOTCHAS HIT DURING THIS WORK (so you don't re-discover them the hard way)
============================================================================

- Compact toolchain does NOT support Windows natively — install/run it under WSL
  (Ubuntu). `compact compile` was run from WSL against the same files (WSL mounts
  the Windows E: drive at /mnt/e/...), so you can keep editing from Windows and
  just shell into WSL to compile.
- The compiled contract's `contract-info.json` / runtime pins an EXACT
  `@midnight-ntwrk/compact-runtime` version it expects (currently 0.16.0). If you
  recompile the .compact file with a newer `compact` CLI version, that expected
  runtime version may bump — check midnight/contracts/commitment/package.json's
  compact-runtime pin still matches, or you'll get a clear
  `CompactError: Version mismatch: compiled code expects X, runtime is Y` — that
  error is fine and expected to guide you, just bump the package.json version and
  `npm install` again.
- @midnight-ntwrk/ledger-v8 must be pinned EXACTLY (not `^8.0.0`) to whatever
  version @midnight-ntwrk/midnight-js-protocol expects internally, or npm
  installs two incompatible copies and TypeScript throws confusing "two
  different types with this name exist" errors. Currently pinned to 8.1.0 —
  if you bump midnight-js-protocol, re-check this.
- Errors thrown by the Midnight SDK are "effect" library tagged objects with a
  custom Node inspect symbol and null prototype — Node's default top-level
  uncaught-exception printer chokes on them and shows almost nothing useful
  (`[Object: null prototype] { [Symbol(nodejs.util.inspect.custom)]: ... }`).
  deploy.ts already wraps its main() in a .catch that force-prints with
  `util.inspect(err, {depth:10, customInspect:true})` — if you write more
  scripts against this SDK, do the same or you'll be debugging blind.
- Use `tsx` to run these TS/ESM files, not `ts-node/esm` — the counter example
  reference uses ts-node/esm but it threw an opaque, unhelpful crash on this
  machine's Node 22; tsx worked and is already what package.json's
  `deploy:preprod` script uses.
- PowerShell env vars are `$env:NAME="value"` on their own line before the
  command, NOT `NAME=value command` (that's bash syntax) — easy to trip on if
  you're copy-pasting between shells.
- The faucet (https://faucet.preprod.midnight.network/) occasionally fails with
  "Failed to prove transaction" — just retry, it's flaky infra, not something on
  our end. An alternate faucet URL was mentioned in some doc summarization
  (midnight-tmnight-preprod.nethermind.dev) but only the one above has been
  confirmed to actually work.
