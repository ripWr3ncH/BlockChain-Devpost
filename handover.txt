1. WHAT'S DONE
============================================================================

A) Compact toolchain — rebuilt from scratch on this machine, compiles clean.
   - `compact update` shells out to `unzip`, which this WSL image lacks, and sudo
     needs a password. Symptom: "Failed to spawn artifact extraction command".
     Worked around with a python3 zipfile shim at ~/.local/bin/unzip that also
     restores each entry's mode from external_attr — a plain extractall drops the
     exec bit and the extracted compactc will not run.
   - Pin the compiler: `compact update 0.31.1`. If a version dir exists but compile
     says "Expecting a file: .../compactc", the artifact downloaded but never
     unpacked; extract artifact.zip in place.
   - WSL mounts this repo at /mnt/g/KUET/... (the old notes said /mnt/e).
   - Driving WSL from Windows: `$HOME` and shell vars get mangled through
     `wsl.exe -- bash -c '...'`. Write a .sh file and run `bash /tmp/x.sh` instead.

B) verifyBoardThreshold — now a REAL k-of-n check (was a stub).
   The old version hardcoded validCount = 0, so every board-authorised transition
   asserted `0 >= boardThresholdK` and could NEVER commit. Write-off, a third-plus
   reschedule, and an upgrade out of a classified tier were all impossible. It now
   counts confirmed, non-revoked, distinct directors whose registered commitment
   matches the preimage supplied in the witness, and discloses only the count.
   Honest scope, also written into the contract's own comments: it proves knowledge
   of a registered commitment's preimage, NOT a signature over the event, so a bank
   holding a director's secret could reuse it for a later vote. Director identities
   are still disclosed (a public Map lookup needs a public key) — what the ZK layer
   buys is credential secrecy, not voter anonymity.

C) Wallet sync — this was the real blocker, and it is now understood.
   A first-time sync replays the entire ledger. Two separate problems:
   - THROUGHPUT: the SDK's default batching walked Preprod's shielded stream at
     ~80 events/s (about five hours) and blew a 6GB heap at index ~83k. The
     shielded wallet's config accepts `batchSize`; at 5,000 the same scan runs at
     ~14,000 events/s with RSS flat near 340MB. Now set in api.ts.
   - WHAT "SYNCED" MEANS: FacadeState.isSynced ANDs all three wallets. Deploying
     only spends unshielded NIGHT and the DUST it generates, so api.ts now gates on
     those two and lets the shielded scan finish in the background. The completion
     predicate compares appliedIndex to **highestRelevantWalletIndex**, not
     highestIndex — highestIndex reads 0 until the stream reports a target, which
     is exactly why a working sync looked hung in the previous session.

D) Network switched to PREVIEW, and this is a measured decision, not a preference.
   The DUST wallet's sync is the binding constraint: its batch size is HARDCODED at
   10 events/tick inside the SDK (wallet-sdk-dust-wallet/dist/v1/Sync.js), so it
   cannot be tuned and runs at roughly 60-280 events/s regardless.
     Preprod stream: ~1,453,000 events  -> over nine hours, and it OOMs first.
     Preview stream:   ~151,000 events  -> tens of minutes. Feasible.
   requirements.txt allows either network. MIDNIGHT_NETWORK=preview|preprod|
   standalone now selects it (default preview); deploy writes
   deployment.<network>.json.
   DEAD END, do not retry: restoring a wallet at a non-zero `offset` to skip
   history fails — the commitment trees must be built linearly and the ledger
   rejects it with "values inserted non-linearly into dust commitment tree".

E) Bridge service (src/bridge.ts) — the Midnight back end, type-checks clean.
   It is a SEPARATE long-lived process for a structural reason: the wallet must
   replay ledger history before it can sign, which takes minutes, so it cannot be
   built per request. It syncs once at boot, holds the wallet + providers, and
   serves circuit calls over HTTP. Endpoints: /health, /contract, /loans, /events,
   /directors/{provision,register,confirm,revoke}, /config.

F) Frontend (web/app/board/page.tsx + web/lib/midnight.ts) — rebuilt in the
   Quorum design system and rendering. Drives the whole demo: constitute a board,
   originate, then attempt a write-off with too few approvals (circuit refuses)
   and again with enough (commits, with a receipt).

3. GOTCHAS (cumulative — earlier ones still valid unless corrected in §0)
============================================================================

- Midnight SDK errors are "effect" tagged objects with a null prototype; Node's
  default printer shows almost nothing. deploy.ts and bridge.ts both force
  util.inspect(err, {depth:10, customInspect:true}). Do the same in new scripts.
- Use `tsx`, not ts-node/esm.
- @midnight-ntwrk/ledger-v8 must be pinned EXACTLY (8.1.0) to what
  midnight-js-protocol expects, or TS reports confusing "two different types with
  this name" errors.
- The compiled contract pins an exact compact-runtime version. contract-info.json
  currently records runtime-version 0.16.0, which matches what the whole npm tree
  dedupes to. Re-check this if you ever bump the compiler.
- PowerShell env vars are `$env:NAME="value"` on their own line, not bash's
  `NAME=value cmd`.
- Do NOT pipe a long-running node script through `grep` when capturing output —
  the pipe fully buffers and you see nothing until it exits. Redirect to a file.
- Windows: `new URL(import.meta.url).pathname` yields "/G:/..." and path.resolve then
  produces "G:\G:\...". Use fileURLToPath. This cost a full 30-minute sync before
  failing with a misleading "cannot read verifier key". src/preflight.ts now checks
  the compiled assets and the proof server BEFORE the sync starts.
- Two installs of @midnight-ntwrk/onchain-runtime-v3 break `instanceof` even at the
  SAME version (two wasm instantiations). Symptom: "expected instance of StateValue".
  It must be one HOISTED copy — an `overrides` entry alone left two nested installs;
  adding it as a direct dependency fixed it. Verify with
  `npm ls @midnight-ntwrk/onchain-runtime-v3`.
- When testing a fix, actually restart the bridge. A stale process keeps the old
  node_modules in memory and will reproduce a bug you have already fixed. Kill by
  port (PowerShell Get-NetTCPConnection -LocalPort 8090) — pkill from git-bash does
  not reliably kill it.
- persistentHash in TS needs a runtime type descriptor:
  persistentHash(new CompactTypeVector(1, new CompactTypeBytes(32)), [secret])
  matches the contract's persistentHash<Vector<1, Bytes<32>>>([x]). The bridge
  derives director commitments this way so browser and circuit cannot drift.
